### R-02 产品架构与跨设备会话

- DSH 部署在服务器，不是在 Android 手机本地完整部署。
- App 是连接服务器的 Android 移动客户端，使不同地点和设备使用相同服务器会话、上下文和工作区。
- 服务器保存权威数据；手机可保存一份本地缓存，重开先显示本地快照再同步服务器，避免每次都像从零加载。

### R-03 极简配对与安全边界

- 配对表单力求简洁。
- 模型 API Key 留在服务器，不能要求用户把各供应商密钥逐个输入手机，也不能写进本地 UI、日志或缓存。

### R-04 原生 DSH 视觉与移动端重排

- 颜色集中为 DSH 已有的黑、白、灰、蓝 token，并增加 Tokyo Night 主题。
- 风格贴近 DSH 原生，不做花哨、霓虹或与 DSH 无关的 AI 壳。
- 能迁移的 DSH Web UI 元素、术语、图标、状态反馈和交互顺序应直接迁移；不能直接复用的部分按原规范做移动端重写。
- 桌面设置弹窗、抽屉和输入框不能只缩放，必须按手机触控、键盘、安全区和横竖屏重新排布。

### R-05 模型与设置必须真实生效

- 会话模型选择必须真正改变服务器当前模型，不能界面选了 Flash、实际始终使用 Pro。
- Cordis/DSH 内置枚举用选择控件，不让用户手输。
- 主题、Agent 预设、权限等每一个设置都必须绑定真实能力并产生效果；服务器不支持时明确说明，不放假开关。
- 模型页不能把所有预置供应商都直接填成用户配置。
- 供应商预设和 icon 可研究 CC Switch 的实现和开源许可，借鉴其配置体验；复用代码前必须核对许可证和与 DSH 协议的适配。

### R-06 品牌与抽屉

- 抽屉顶部使用黑色鲸鱼加 `DeepSeek Harness`，与 DSH Web 一致，不再只写 `DSH`。

- 设置入口上方显示当前 DeepSeek API 余额。
- 底部增加横竖屏切换 icon，并保证是真实 Android 屏幕方向能力。

### R-07 DSH 原生输入框能力

- 模型与推理等级放在同一组交互中。
- 保留 DSH 蓝底发送/运行状态 icon 的切换与反馈。

### R-08 文件与图片

- 输入框增加统一风格的文件/图片上传入口，可使用曲别针或圆形加号。

- 普通文本/代码文件可以受限转文本；尚无服务端解析能力的 PDF、Office、压缩包等不得假装上传成功。
