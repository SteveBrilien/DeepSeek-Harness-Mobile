# v1.0 验收标准

## 纵向链路

1. 新安装 App 可用一次性配对码绑定服务器。
2. 会话列表来自 DSH `session.list`，不出现演示数据。
3. 可创建会话、发送消息并逐段显示真实 `session/event`。
4. 工具 call/result、reasoning、turn/end 在刷新后可由 history 恢复。
5. 可停止运行；断网重连后不会重复用户消息或丢失已持久事件。
6. 审批可以拒绝或仅本次允许，答案与对应 `rpcId`、session、approval id 绑定。
7. 权限与模型选择显示服务端真实选项，切换失败必须回滚 UI。
8. 二次冷启动先显示本地缓存，再在后台与同一服务器会话增量校准；清除缓存后服务端会话仍可完整恢复。
9. 离线可浏览缓存与编辑草稿，但不能排队发送、审批或修改服务器设置。

## UI 设备矩阵

- 360×800、393×873、412×915。
- 竖屏与横屏。
- 软键盘打开、输入器多行、底部导航条与刘海安全区。
- 亮色、深色、130% 字体、减少动态效果。

## 禁止项

- 零模拟回复、模拟余额、模拟 token 统计。
- 零明文 API key、设备 token、签名口令。
- 零 `file://` 主页面和 `MIXED_CONTENT_ALWAYS_ALLOW`。
- 零通配 CORS；零任意 URL 的 WebView 内导航。
- release APK 不得使用仓库内 keystore。

## 性能

- 冷启动到配对/会话骨架：中端设备 2 秒内。
- 有缓存的二次启动到最近会话可读内容：中端设备 300ms 内。
- 输入到本地 optimistic 状态：100ms 内。
- token chunk 以帧批次渲染，前台更新不高于约 20 次/秒。
- 500 条消息时滚动和输入保持可交互。
